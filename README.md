# Battle for Rokugan Online

Браузерная версия настольной игры «Битва за Рокуган». Клиент написан на React и Vite, API работает в Cloudflare Worker, а состояние каждой комнаты хранится в отдельном Cloudflare Durable Object.

## Требования

- Node.js 22.13 или новее;
- npm;
- Git;
- аккаунт Cloudflare нужен только для облачного деплоя.

Версия Node для проекта указана в `.node-version`. Зависимости зафиксированы в `package-lock.json`, поэтому для обычной установки используйте `npm ci`.

## Локальный запуск

```powershell
git clone https://github.com/MORTEM3845/Battle-for-Rokugan-Online.git
cd Battle-for-Rokugan-Online
npm ci
npm run dev
```

Vite напечатает локальный адрес, обычно `http://localhost:5173`.

Если политика выполнения PowerShell блокирует `npm.ps1`, используйте те же команды через `npm.cmd`, например:

```powershell
npm.cmd ci
npm.cmd run dev
```

## Проверки перед коммитом

```powershell
npm run typecheck
npm run test:rules
npm run build
npm run preview
```

- `typecheck` проверяет TypeScript клиента, Worker и общих типов;
- `test:rules` воспроизводит спорный сценарий погрома в Землях Теней, ронина, сюгэндзя, защитные победы и ключевые правила подсчёта;
- `build` создаёт production-сборку клиента и Worker;
- `preview` запускает собранное приложение локально в Workers runtime.

Перед отправкой крупного изменения полезно открыть игру в двух разных браузерах или в обычном и приватном окне, создать комнату, присоединиться вторым игроком, сделать несколько ходов и обновить обе страницы.

## Локальное хранилище Durable Objects

При локальной разработке комнаты сохраняются в `.wrangler/state`. Эта папка игнорируется Git.

Важно:

- локальные комнаты не загружаются в Cloudflare при деплое;
- облачный Worker после первого деплоя начинает с пустого набора комнат;
- локальное и облачное хранилища полностью независимы;
- удаление `.wrangler/state` сбрасывает только локальные комнаты.

## Подготовка первого Cloudflare-деплоя

Деплой выполняется как Cloudflare Worker со статическими ресурсами и Durable Object `RoomObject`. Для первой проверки лучше использовать адрес `workers.dev`, а собственный домен подключить после smoke-теста.

Текущая декларация `exports.RoomObject` рассчитана на первый реальный деплой этого Worker. Если Worker с именем `battle-for-rokugan-online` уже публиковался с legacy-миграцией `v1`, сначала проверьте его удалённую историю и не переключайте жизненный цикл Durable Object вслепую.

Из корня проекта выполните:

```powershell
node --version
npm ci
npm run typecheck
npm run deploy:dry
```

Версия Node должна быть 22.13 или новее. `deploy:dry` собирает проект и проверяет итоговую конфигурацию Wrangler, но ничего не публикует.

Затем авторизуйтесь:

```powershell
npx wrangler login
npx wrangler whoami
```

Если к учётной записи привязано несколько аккаунтов Cloudflare, убедитесь, что выбран нужный.

## Деплой

```powershell
npm run deploy
```

Команда сначала повторно собирает проект, затем публикует Worker. При первом запуске Wrangler может попросить выбрать аккаунт или настроить поддомен `workers.dev`.

Не запускайте деплой из каталога со старой сборкой вручную: штатная команда `npm run deploy` всегда создаёт актуальные файлы для Cloudflare Vite Plugin.

## Smoke-тест после деплоя

Wrangler напечатает публичный адрес приложения. Сразу проверьте:

1. Откройте `<PUBLIC_URL>/api/health`. Ожидаемый ответ:

   ```json
   { "status": "ok" }
   ```

2. Откройте `<PUBLIC_URL>` и создайте комнату.
3. Присоединитесь к ней из приватного окна или со второго устройства.
4. Запустите игру и выполните несколько действий обоими игроками.
5. Обновите обе страницы и убедитесь, что сессии и состояние комнаты восстановились.
6. Закройте страницы, откройте комнату снова и проверьте облачное сохранение.

Для просмотра живых логов Worker используйте отдельный терминал:

```powershell
npx wrangler tail
```

Остановить просмотр можно сочетанием `Ctrl+C`.

## Важные правила для облачного хранилища

- Не переименовывайте Worker `battle-for-rokugan-online` после запуска без отдельного плана миграции.
- Не переименовывайте класс или декларацию `exports.RoomObject` без отдельного плана миграции Durable Objects.
- Декларация `exports` является источником истины для жизненного цикла Durable Object. После её первого облачного применения не возвращайтесь к старому массиву `migrations`.
- Откат версии Worker не откатывает данные Durable Objects. Изменения формата комнаты должны сохранять обратную совместимость или иметь собственную миграцию данных.
- Повторный деплой того же Worker с тем же Durable Object binding сохраняет облачные комнаты.

Если новая версия Worker работает неверно, сначала остановите дальнейшие деплои, посмотрите `wrangler tail` и только затем принимайте решение об откате:

```powershell
npx wrangler rollback
```

Помните, что эта команда откатывает код, но не состояние комнат.

## Автоматический деплой

Для первого запуска рекомендуется ручной деплой. Позже в GitHub Actions можно сохранить:

- `CLOUDFLARE_API_TOKEN`;
- `CLOUDFLARE_ACCOUNT_ID`.

Эти значения должны находиться только в GitHub Actions Secrets или в локальном защищённом окружении. Их нельзя добавлять в Git, README, `.env` или исходный код.

## Структура

- `src/` — React-интерфейс;
- `worker/` — Cloudflare Worker и Durable Object комнаты;
- `shared/` — общие типы и данные клиента и сервера;
- `public/` — статические ресурсы;
- `wrangler.jsonc` — конфигурация Cloudflare;
- `vite.config.ts` — конфигурация Vite и Cloudflare Vite Plugin.
